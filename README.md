# Test_task_for_first_IT_company
# Чек на удачу

Веб-приложение для проведения промоакции «Чек на удачу». Пользователи могут регистрировать чеки за покупки, просматривать их статусы в личном кабинете, а модераторы — проверять зарегистрированные чеки и принимать решение об их одобрении или отклонении.

Проект разработан в рамках тестового задания.

## Технологический стек

- **Python**
- **Django**
- **PostgreSQL**
- **Docker / Docker Compose**
- **HTML, CSS, JavaScript**

## Реализованный функционал

### Аутентификация
- Регистрация и авторизация пользователей средствами `django.contrib.auth`.
- Разграничение доступа к пользовательским данным.

### Регистрация чеков
- Форма регистрации чека со следующими полями:
  - ФН — фискальный накопитель;
  - ФД — фискальный документ;
  - ФП — фискальный признак;
  - дата и время покупки;
  - сумма покупки.
- Серверная валидация данных.
- Проверка соответствия даты покупки периоду акции.
- Проверка минимальной суммы покупки — 1000 ₽.
- Проверка уникальности комбинации ФН + ФД + ФП.
- Автоматическое присвоение новым чекам статуса «На проверке».
- Обработка ошибок с понятным информированием пользователя.

### Личный кабинет
- Отображение списка чеков текущего пользователя.
- Информация о дате покупки, сумме, статусе и причине отказа.
- Сортировка от новых чеков к старым.
- Пагинация по 10 записей на страницу.
- Кнопка перехода к регистрации нового чека.

### Модерация
- Использование стандартной административной панели Django.
- Доступ к модерации для пользователей с флагом `is_staff`.
- Возможность просматривать зарегистрированные чеки и изменять их статусы.
- Указание причины при отклонении чека.

### API
Реализован эндпоинт:

`GET /api/receipts/`

Возвращает чеки авторизованного пользователя в формате JSON.

Доступ к данным ограничен текущим пользователем: API не возвращает чужие чеки.

API может вызываться пользователем через кнопку. Эти чеки выйдут снизу(Вообще я продуманно не оформлял Frontend для этих JSON записей)

### Интерфейс
- Реализованы страницы регистрации чека и личного кабинета.
- Вывод периода акции на основе настроек проекта.
- Клиентская проверка обязательных полей и форматов.
- Отображение ошибок рядом с соответствующими полями без перезагрузки страницы.
- Отправка формы с помощью Django POST.
- Отображение результата отправки на странице с отдельным представлением успешного ответа и ошибки.
- Адаптация интерфейса для мобильных устройств.

## Запуск проекта

### Требования
Для запуска необходимы:
- Docker;
- Docker Compose.

### Установка и запуск

1. Клонировать репозиторий:

   ```bash
   git clone https://github.com/Egorka05284/Test_task_for_first_IT_company
   cd project_root
   ```

2. Создать файл `.env` на основе примера:

   ```bash
   cp .env.example .env
   ```

3. Заполнить необходимые переменные окружения в `.env`. В частности, указать настройки базы данных, секретный ключ Django и даты начала и окончания акции.

4. Запустить проект:

   ```bash
   docker compose up --build -d
   ```

5. Выполнить миграции базы данных:

   ```bash
   docker compose exec web python manage.py migrate
   ```


6. Создать пользователя для доступа к административной панели:

   ```bash
   docker compose exec django-web-promo python manage.py createsuperuser
   ```

После запуска приложение будет доступно по адресу:

`http://localhost:8000/`

Административная панель Django:

`http://localhost:8000/admin/`

## Настройки окружения

Все параметры, зависящие от окружения, хранятся в `.env`.

В `.env.example` представлены необходимые для запуска переменные, включая даты начала и окончания промоакции.

Реальные секреты и конфиденциальные настройки не должны попадать в репозиторий.

## Принятые решения

В рамках задания некоторые ситуации требовали самостоятельного определения логики работы приложения.

**1. Повторная регистрация отклонённого чека**

Повторная регистрация одного и того же чека не допускается независимо от его текущего статуса. Уникальность определяется комбинацией ФН + ФД + ФП.

Таким образом, отклонённый чек нельзя зарегистрировать повторно. Это предотвращает повторное использование одного чека в рамках акции.

**2. Границы периода акции**

Даты начала и окончания акции задаются через переменные окружения.

Обе границы периода включительны: покупка в первый и последний день акции считается допустимой. Дата и время покупки интерпретируются в часовом поясе, установленном в настройках Django (`TIME_ZONE`), независимо от часового пояса браузера пользователя.

**3. Статус нового чека**

Каждый успешно зарегистрированный чек получает статус «На проверке». Пользователь не может самостоятельно изменять статус — решение принимает модератор.

**4. Доступ к чекам через API**

API возвращает только записи, принадлежащие авторизованному пользователю. Получение чужих чеков через параметры запроса не предусмотрено.
